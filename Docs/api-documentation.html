Authentication

All protected endpoints require a Firebase ID token passed in the Authorization header:

Header Authorization: Bearer <firebase_id_token>

Token Source

Firebase ID tokens are obtained through:

  • OTP verification flow
  • Password login (returns customToken → exchange for idToken)
  • Token refresh endpoint

Token Lifecycle

  • ID tokens expire in ~1 hour
  • Use refresh token to get new ID token
  • Refresh proactively (5 min before expiry)
  • Custom claims: role, userId

Auth Flow — Web & Mobile

OTP Login Flow

1. Verify Credentials
/api/v1/auth/verify-credentials
→
2. Send OTP
Web: /api/v1/auth/send-otp
Flutter: Firebase SDK
→
3. Verify OTP
Web: /api/v1/auth/verify-otp
Flutter: /api/v1/auth/verify-token
→
4. Authenticated ✓
idToken + refreshToken
Flutter difference: The Flutter app uses Firebase Flutter SDK to handle OTP natively (step 2). After OTP verification, Flutter gets a Firebase ID token directly from the SDK. Send this token to /api/v1/auth/verify-token to complete login and get the user profile.

Password Login Flow

1. Login
POST /api/v1/auth/login
→
2. Receive customToken
From API response
→
3. Exchange Token
signInWithCustomToken()
via Firebase SDK
→
4. Authenticated ✓
idToken + refreshToken
Password login works the same for web & Flutter. Call the API, get the customToken, then use Firebase SDK's signInWithCustomToken() to get the idToken for subsequent authenticated API calls.

Error Handling

All endpoints return consistent JSON error responses:

Error Response { "success": false, "error": "Human-readable error message" }

POST /api/v1/auth/verify-token Verify Firebase token (Flutter primary) PUBLIC ▾

Verifies a Firebase ID token and returns the user profile. This is the primary login endpoint for Flutter after OTP verification via Firebase SDK.

Request Body
FieldTypeRequiredDescription

POST /api/v1/auth/login Login with phone/email + password PUBLIC ▾

Authenticate with phone number or email and password. Returns a Firebase custom token that must be exchanged for an ID token using signInWithCustomToken().

Request Body
FieldTypeRequiredDescription
identifierstringREQUIREDPhone number or email address
passwordstringREQUIREDAccount password
Success Response — 200
{ "success": true, "customToken": "eyJhbGciOi...", "user": { "id": "7999952226", "name": "John", "phone": "7999952226", "role": "USER", "allowedScreens": null } }
Important: The response contains a customToken, NOT an idToken. You must exchange it:
await FirebaseAuth.instance.signInWithCustomToken(customToken)
Then get the idToken from the resulting UserCredential for subsequent API calls.

400 401 403 429

Shared Libraries (src/lib/)

Initializes Firebase Admin SDK. Exports adminDb (Firestore) and adminAuth (Auth). Strips BOM/CRLF from env vars.

auth.js

verifyAuth(request) — validates Bearer token, returns user object. verifyAdmin(request) — same + checks role is ADMIN.

response.js

Consistent JSON responses with CORS headers. success(data), error(msg, status), json(data, status).

email.js

Resend integration for 3 email types: new registration (admin), user approved, new enquiry (admin). Lazy-initializes Resend client.

Flutter Integration Notes

Key details for the Flutter mobile app developer

Auth Integration Summary

OTP Login (Flutter)

  • Call /api/v1/auth/verify-credentials with phone
  • Use Firebase Flutter SDK verifyPhoneNumber()
  • After OTP verified, get idToken from SDK
  • POST idToken to /api/v1/auth/verify-token
  • Store idToken + refreshToken securely

Password Login (Flutter)

  • POST phone + password to /api/v1/auth/login
  • Receive customToken in response
  • Call signInWithCustomToken()
  • Get idToken from UserCredential
  • Use idToken for all API calls

Token Management

Auto-refresh: Firebase ID tokens expire after ~1 hour. Implement a token refresh interceptor in your HTTP client. When you get a 401 response, call /api/v1/auth/refresh with the stored refreshToken, save the new tokens, and retry the failed request.

All API Calls Pattern

Dart / Flutter // Every authenticated API call follows this pattern: final response = await http.get( Uri.parse('https://unique-backend-dun.vercel.app/api/v1/enquiry'), headers: { 'Authorization': 'Bearer $idToken', 'Content-Type': 'application/json', }, ); final data = jsonDecode(response.body); if (data['success'] == true) { // Handle data['data'] or data['user'] } else { // Handle data['error'] }

Role-Based Access

The user object contains a role field ("USER" or "ADMIN") and an allowedScreens array. Use these to control what screens the user can access in the Flutter app:

  • allowedScreens: null → user has access to all screens
  • allowedScreens: ["enquiry", "quotation"] → user can only access those screens
  • Admin users always have full access

Phone Number Format

All phone numbers in this API are 10-digit Indian format (e.g., 7999952226). Do NOT include country code (+91) when sending to the API. The API validates with regex /^[6-9]\d{9}$/.

Firebase Configuration

The Flutter app needs to use the same Firebase project as the web app. Get the Firebase config from the project admin. Required Firebase products:

  • Authentication — Phone auth provider must be enabled
  • Firestore — Used for data storage (but accessed via API, not directly)
Important: The Flutter app should NOT read/write Firestore directly. All data operations go through the API endpoints. Firebase SDK in Flutter is only used for authentication (OTP verification + signInWithCustomToken).
