Admin & Permissions Phase 1 · Delivered

Why this matters for Frontend: — the UI must expose admin-only controls (delete buttons, bank-edit fields, dropdown editors, pricing panel, mandatory/optional toggles) and hide them for normal users.
Step 1
Give Admin Full Access to All Enquiry Forms shared
Admin should be able to view, edit, add, and change any field in every enquiry form — including enquiries created by other users. Frontend: show edit/add controls for Admin only.
Also in Backend: RBAC checks on enquiry read/write/update endpoints — Admin role bypasses ownership checks.
Step 2
Only Admin Can Delete Enquiry Forms shared
Remove the delete option from normal users. Only Admin should be able to delete enquiries. Frontend: hide the delete button in row actions / detail view for non-admins.
Also in Backend: DELETE /api/v1/enquiry/:id must verify role === 'ADMIN' before allowing deletion.
Step 3
Bank Details — Admin Only
Bank details in the quotation should be editable only by Admin. Frontend: disable / hide the bank-details editor for non-admin roles; show as read-only text in the preview.
Step 4
Admin Access to Add/Edit States, Lead Sources & Dropdown Values
Frontend: build a settings panel where Admin can add/edit/delete States, Lead Sources, and other dropdown options inline.
Client said: "Aaj hum do state mein kar rahe hain, kal hum teen state mein karenge — ye sab kahan set kar payenge? Ye access humko chahiye."
Step 5
Admin Access to Add/Edit Models, Sizes & Pricing
Frontend: settings panel to add new machine models, sizes, and update pricing.
Client said: "Future ke liye agar humko add karna hai toh uska access hum mein rahe toh zyada better hai taki hum kabhi bhi edit kar sakein."
Step 6
Admin Access to Mandatory/Optional Field Settings
Frontend: toggle UI to mark each enquiry field as required or optional; reflect this on form validation messages.
