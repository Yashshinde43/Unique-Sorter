Development Roadmap — Step-by-Step Updates

This document lists all 15 changes requested for the CRM app, arranged in the correct order a developer should follow. Each phase builds on the previous one. Start from Phase 1 and go down.

How to read this document
The updates are arranged in 5 phases, numbered from Phase 1 to Phase 5. Each phase must be completed before moving to the next one, because later features depend on earlier ones. Within each phase, the steps (Step 1, Step 2, etc.) can be done in any order. The "Why do this first?" note under each phase explains the reason for the ordering.
1 Permissions & Access 3 steps
2 Remove & Add Fields 3 steps
3 Form Features 4 steps
4 Quotation Fixes 3 steps
5 Communication 2 steps
1

Permissions & Access Control

Why do this first? — Permissions are the foundation. If we add new fields or features first, we won't know who can see or edit them. Setting up Admin vs. User access first means every future feature automatically respects the rules.
Step 1
Give Admin Full Access to All Enquiry Forms
Admin users should be able to view, edit, add, and change any field in every enquiry form. No restrictions for Admin.
Currently
Admin may not be able to edit some fields in enquiries created by other users.
After Update
Admin opens any enquiry and can change anything — name, status, amounts, all fields.
Step 2
Only Admin Can Delete Enquiry Forms
Remove the delete button/option for normal users. Only Admin should see and use the delete option on enquiry forms.
Currently
Any user can delete enquiry forms, which is risky.
After Update
Normal users see no delete option. Only Admin can delete.
Step 3
Bank Details Field — Admin Only
The Bank Details field should be completely hidden from normal users. Only Admin users should be able to see and edit bank information.
Currently
Everyone can see the bank details field.
After Update
Only Admin sees the bank details section. Other users see nothing there.

2

Remove & Add Fields

Why do this second? — Before building features on top of the form, we need to clean up the form structure itself. Remove what's not needed, add what's missing. This avoids building features on fields that will later be deleted.
Step 4
Remove "Electronics" Field & "Warranty" Field
These two fields are no longer needed. Delete them from the enquiry form and from the database. They should not appear anywhere in the app.
Step 5
Add New Fields: Immediate / No-Future / Follow-up
Add a new classification to enquiries with three options: Immediate (urgent enquiry), No-Future (not interested), and Follow-up (will check later). This should appear in both the enquiry form and in the table/grid view.
Currently
No way to classify how urgent or important an enquiry is.
After Update
Every enquiry gets a tag: Immediate, No-Future, or Follow-up — visible in the form and in the list.
Step 6
Set Default Delivery Point to "Raipur"
When creating a new enquiry or quotation, the Point of Delivery should automatically show "Raipur". The user can change it if needed. After selecting delivery point, they can choose the freight option.
↓ ↓ ↓
3

Form Features & Workflow

Why do this third? — Now that permissions are set and form fields are finalized, we can safely build features like log history, remarks, customer search, and stage alerts on top of the correct structure.
Step 7
Remark Field — Make It Compulsory & Keep History
The Remark field should be mandatory — users must write something. When a new remark is added, old remarks should NOT be deleted. All remarks should be saved as a timeline log, one below the other with date and time.
Example: If a user writes "Called customer, will follow up tomorrow" on June 25, and then adds "Customer confirmed the order" on June 27 — both entries should be visible as a log. The old one stays, the new one gets added on top.
Step 8
Enquiry Form — Complete Log History
Every change made to an enquiry form should be automatically recorded — what was changed, who changed it, and when. This lets Admin track the full history of every enquiry.
Currently
No record of who changed what in an enquiry.
After Update
A "History" section shows: "Rahul changed Status from New to In Progress on 25 June at 3:30 PM" — for every change.
Step 9
Add Existing Customer in Customer Field
When creating a new enquiry, the user should be able to search and select an existing customer from a dropdown list, instead of typing the same customer's details again every time.
Currently
User has to type the customer name and details manually every time, even for repeat customers.
After Update
User starts typing a customer name, a dropdown shows matching existing customers, and clicking one fills in all their details automatically.
Step 10
Stage Change Alerts
When someone changes the stage of an enquiry (e.g., from "New" to "Quotation Sent"), an alert or notification should appear so the team knows the enquiry has moved forward.
↓ ↓ ↓
4

Quotation Page Fixes

Why do this fourth? — Quotation pages are generated from enquiry data. Now that the form structure and data are correct, we can safely fix how quotations look — logo, margins, and formatting.
Step 11
Make Logo Same on Both Quotation Pages
The two quotation pages currently show different logos. Both pages should display the same company logo for a professional, consistent look.
Currently
One quotation page has a different logo than the other.
After Update
Both quotation pages show the exact same Unique Sorter logo.
Step 12
Fix Left Margin — Content Should Start from the Left
The quotation content should start closer to the left side of the page, like how we type in Microsoft Word. Right now there is too much empty space on the left. Some space on the right side is fine.
Step 13
Fix Rupee Symbol & Number Formatting in Detailed Quotation
In the detailed quotation view, the Rupee symbol (₹) and number formatting is broken or inconsistent. All currency amounts should display properly with the ₹ symbol and correct number format (e.g., ₹1,25,000).
↓ ↓ ↓
5

Communication & Snapshot

Why do this fifth? — Email and WhatsApp features work best when all the form data, quotation formatting, and permissions are already correct. Snapshot also makes more sense once the UI is finalized.
Step 14
Email & WhatsApp Options for Suppliers and Users
Add both Email and WhatsApp buttons/options so that suppliers and users can be contacted through either channel directly from the app.
Step 15
Snapshot Feature
Add a snapshot button that lets users capture and save the current state of a record or screen — like taking a photo of the data at that moment for reference.
